Two's Complement

How should we represent negative numbers in binary? In considering this question, we should consider what a "negative number" fundamentally is. It is the additive inverse of a positive number. That is:

\[X + (-X) = 0\]

So, we are looking for a binary number, \((-X)\), that we can add to a positive binary number, such that the sum is equal to zero. Can we find such a number, without changing the process of addition? To do so, remember that computers are finite. As we increment or add to a binary number, we will eventually reach a magnitude limit. For example, what happens if we increment 11112 by 1? We get 100002, right? But what if only 4 bits of memory have been allocated to representing this integer? Then the value will overflow from 100002 to just 00002. Ah! We did it! We found that 12 is indeed the additive inverse of 11112. This may not be obvious at first, but it is true, in a modulo 16, or \(\mod{2^4}\) system. It is natural to interpret digitally represented numbers as \(\mod{2^n}\) systems, because of the fact that computer memory is finite.

To represent negative binary integers correctly, we must know the number of bits used to represent the integer. In a 4-bit system, the additive inverse of 1 is 11112. In an 8-bit system, the additive inverse of 1 is 111111112. Can you find the additive inverse of 102? How about, of 112?

We can use a simple algorithm to find the additive inverse, or negative, of any binary number. Here it is.

Two's Complement Additive Inversion

To find the additive inverse of a number in Two's Complement format:

  1. Convert to binary: Write the number in binary form. Pad it with zeros on the left to fill a certain fixed bit width (e.g., 8 bits).
  2. Invert all bits: Flip every 1 to a 0, and every 0 to a 1. (This is known as the One's Complement).
  3. Add 1: Add 1 to your inverted binary value.

Try it yourself. Choose a positive number, and use this algorithm to find its additive inverse. Then, use binary arithmetic to add the result to the original number. Cut off any extra bits from the left, to limit the result to the original bit width. Is the sum zero?

Why does it work?

When you add a binary number to its own bitwise logical complement, you are adding a 0 and a 1, in each binary place. Thus, the result of this addition is always 1111...., for every bit of the fixed width \(n\). In other words, adding \(X\) and \(\overline{X}\) produces an \(n\)-bit value where every bit position contains 1:

\[X + \overline{X} = \sum_{i=0}^{n-1} 1 \cdot 2^i \]

Using the geometric series identity \(\sum_{i=0}^{n-1} 2^i = 2^n -1\):

\[X + \overline{X} = 2^n - 1\]

Adding 1 to both sides:

\[X + (\overline{X} + 1) = 2^n\]

In a \(\mod{2^n}\) system,

\[2^n \equiv 0\]

So

\[X + (\overline{X} + 1) \equiv 0\]

Remembering the definition:

\[X + (-X) = 0\]

Leaves:

\[-X \equiv \overline{X} + 1\]

Q.E.D.

Subtraction

Now that we have a formula for the additive inverse of binary numbers, we can do subtraction operations by using:

\[A - B = A + (-B)\]

or:

\[A - B = A + (\overline{B} + 1)\]
